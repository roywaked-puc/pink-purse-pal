# Architecture rules
- Keep account deletion in service-only lifecycle functions with Stripe ownership checks and retry-safe refunds; a managed daily adapter authenticates scheduling and forwards the separate purge secret, while transactional purge locks all affected tables before temporarily disabling user triggers.
- Serialize account billing actions with service-only claims and preserve refunded subscription IDs in a private ledger; delayed webhooks and reopening must never restore refunded access or renew billing, and retry eligibility uses the original request timestamp.
- Classify monetary barter exclusions only through `isTransacaoPermuta` using ID precedence over legacy text in the user's scoped accounts; real receipts on barter appointments must remain money.
- Gate barter form behavior on the persisted activation cut, derive completion credit with the same view eligibility, and classify settlements via ledger transaction IDs before exposing mutations; this preserves legacy forms and settlement consistency.
- Check client barter balances in both the delete hook and an invoker database trigger; the trigger prevents bypassing the UI safeguard.
- Keep barter activation in the invoker RPC `ativar_conta_corrente_permuta`, recalculating reviewed balances and saving the cut and initial entries atomically; only explicit confirmed activation may call it.
- Build barter statements and WhatsApp periods with `permutaExtrato` and fetch/write ledger data through `usePermuta`; shared card/forms keep client and general-list balances consistent.
- Keep barter legacy detection in the invoker view `permuta_transacoes_legadas`, with account_id precedence and same-owner text fallback only for null account_id; preserve legacy rows to prevent migration double counting.
- Record barter cash settlements through the invoker RPC `registrar_acerto_permuta`; freeze settlement financial fields and initial/settlement ledger rows in database triggers to keep both sides consistent.
- Keep subscription entitlement in authenticated no-argument RPCs and enforce expiry only on appointment INSERT; signed Stripe invoice.paid events grant paid access atomically with internal event deduplication, never through client writes or business transactions.
- Keep public legal documents in `src/content/legal.ts` and render them outside ProtectedRoute/MainLayout; public reading must not require a session or show business navigation.
- Confirm user-settings writes with an explicit safe-column readback; onboarding closes only after a persisted completion timestamp, so write errors cannot masquerade as success.
- Derive confirmation reminders from appointments already in AppContext using pure helpers; one shared Home/CRM component records only the sent timestamp, keeping status and finance independent.
- Read Google credential availability through an authenticated boolean RPC; safe settings column grants must never expose access tokens, refresh tokens or client secrets.

- Resolve appointment service colors through `getCorServico`; this keeps the fixed maintenance color consistent across every view.
- Keep `AppointmentPreview` exclusive to the Home page; Home layout changes must not alter the Agenda or shared appointment chips.
- Keep attendance completion free of follow-up callbacks or photo prompt state; manual photo access remains independent of status changes.
- Generate future agenda WhatsApp messages in the pure `agendaWhatsapp` helpers and reuse the existing service-description and WhatsApp-link helpers; this keeps eligibility and formatting reusable without changing other flows.- Compute 'days since last attendance' only via `src/lib/diasDesdeUltimoAtendimento.ts`; Home/Agenda chips and the client file must never diverge.

- Keep Help Center content static in `src/content/manual.ts`; the `/ajuda` page renders from it. The first-steps checklist status is derived from real user data in the single `usePrimeirosPassos` hook, and its Home "hide" flag lives in `user_settings.primeiros_passos_oculto_em` so it survives domains and devices.
- Keep Help AI inference in the authenticated `chat-ajuda` Edge Function with a synchronized text-only manual and no data queries/tools; send only the last ten messages capped at 1,000 characters and clear in-memory chat on close to preserve its privacy boundary.
- Decide appointment payment badges and cash pending only via `situacaoPagamento`/`saldoAReceberEmDinheiro` in `src/lib/permuta.ts`; post-cut barter appointments keep stored payment fields untouched but never count as receivable.
- Treat `https://app.belafy.com.br` as the app's primary address in user-visible text and docs, and keep every address that actually serves the app listed in the payment origin allowlist in `supabase/functions/_shared/assinaturas.ts`; this keeps checkout working from each served address.
- Generate the user backup zip client-side in `useGerarBackup` (pure formatting in `src/lib/backup.ts`), reading every table paginated straight from the database, never AppContext; anamnesis PDFs come from `gerarPdfAnamnese` in `src/lib/anamneseImpressao.ts`, which shares sections/answer labels with the print view, and `user_settings` uses the exported safe column list.
